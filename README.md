# 🧠 NeuroViz

**NeuroViz** — это инструмент для аудио-визуализации нового поколения. Вместо примитивных эквалайзеров он использует многослойный DSP-анализ (Digital Signal Processing), чтобы извлекать из музыки семантические события (удары, смену секций, высоту тона, стереопанораму), и транслирует их в визуальный движок для создания синестетического опыта.

Проект разделен на **Анализатор (Avalonia/C#)** и **Визуализатор (Godot/C#)**, которые общаются через высокоскоростной IPC-мост.

## ✨ Ключевые возможности

*   **Многоуровневый анализ:** От простых спектральных полос до предсказательного кодирования (поиск «сюрпризов»).
*   **Детекторы событий:**
    *   `Onset` (атаки, удары).
    *   `Novelty` (смены секций, новизна).
    *   `Pitch` (высота тона через HPS).
    *   `Azimuth` (стереопанорама через ILD).
    *   `Spectral Features` (гармоничность и центроид/яркость).
*   **Разделение Live и Replay:** Анализ происходит на лету, но результаты сохраняются в память, позволяя перематывать трек и видеть визуализацию заново без повторного анализа.
*   **Движок правил (JSON):** Позволяет гибко настраивать маппинг между событиями и параметрами визуализации.
*   **Изоляция процессов:** Если Godot упадет, инспектор продолжит работать.
*   **Debug-инспектор:** Встроенный просмотр спектрограмм и логов событий.

## 🏗 Архитектура

Проект состоит из следующих C#-проектов:

1.  **`NeuroViz.Core`** — Ядро. Схемы событий, контракты IPC, движок правил (RuleEngine).
2.  **`NeuroViz.Audio`** — Аудио-движок. Обертка над `ManagedBass`, извлечение PCM-сэмплов, аудио-клок.
3.  **`NeuroViz.Analysis`** — DSP. Спектрограмма (STFT), детекторы событий (Onset, Novelty, Pitch и др.).
4.  **`NeuroViz.Project`** — Сериализация. Сохранение таймлайнов и настроек в бинарный формат `.nvproj` (MessagePack).
5.  **`NeuroViz.App`** — UI. Инспектор на базе Avalonia (плеер, таблица событий, таймлайн).
6.  **`NeuroViz.Visualizer`** — Рендер. Проект Godot 4, который принимает параметры и рисует визуал.

### 📡 Как это работает (IPC)

1.  **Named Pipes** (`NeuroViz.Control` и `NeuroViz.EventStream`) передают команды управления и кадры событий/параметров от Avalonia к Godot.
2.  **Memory-Mapped File** (`NeuroViz.AudioClock`) используется для передачи точного времени воспроизведения (Audio Clock) без накладных расходов на сериализацию каждый кадр.

## 🛠 Требования

*   **.NET SDK 10.0** — для сборки `NeuroViz.App`, `NeuroViz.Audio`,
    `NeuroViz.Analysis`, `NeuroViz.Project`, `NeuroViz.Tests`.
*   **.NET 8 runtime** — для запуска `NeuroViz.Visualizer` (Godot 4.7
    целится в net8.0). Альтернатива: `DOTNET_ROLL_FORWARD=Major`,
    чтобы запускать визуализатор на runtime .NET 10.
*   **Godot 4.x** (обязательно версия **.NET** / Mono).
*   **BASS Audio Library** — `src/NeuroViz.Audio/native/win-x64/bass.dll`
    (включён в репозиторий).

## 🚀 Быстрый старт

1.  Клонируйте репозиторий:
    ...
2.  Соберите решение:
    dotnet build
3.  Запустите Инспектор:
    dotnet run --project src/NeuroViz.App
4.  Использование:
    *   **Open…** → выбрать аудиофайл.
    *   **Play** → проигрывание + live-анализ.
    *   **Launch Visualizer** → при первом запуске откроет диалоги поиска
        Godot (`Godot_v4.x-stable_mono_win64.exe`) и папки с
        `project.godot` (`src/NeuroViz.Visualizer`). Пути сохраняются в
        `%APPDATA%/NeuroViz/settings.json`. Повторный клик запускает
        Godot без диалогов.
    *   **Settings…** → форма с тремя полями (Godot EXE, project folder,
        rules JSON) вместо ручного редактирования `settings.json`.
        Валидация при Save: файлы/папки должны существовать, JSON
        правил должен парситься. Кнопка **Reset to defaults** обнуляет
        все три поля (не сохраняя).
    *   **Re-analyze** → перезапуск детекторов по загруженному аудио
        (1× скорости). Полезно после Load project для заполнения
        спектров из v1-проектов. Отмена — Stop.

### ⌨️ Горячие клавиши

| Клавиша | Действие |
|---|---|
| `Space` | Play / Pause (toggle) |
| `←` | Перемотка назад на 5 с |
| `→` | Перемотка вперёд на 5 с |
| `Home` | В начало трека |

Работают, пока окно в фокусе. Исключения: фокус в текстовом поле
(печатаешь — не мешаем) или идёт перетаскивание ползунка позиции
(иначе play/pause во время drag = хаос).

`←`/`→` ограничены `[0, Duration]` — на границах трека перемотка
упирается в край, а не перескакивает за него.

### 🎨 3D-визуализатор (Phase 2)

Основной визуал — 3D-сцена в Godot (`MainNode3D` / `spike.tscn`):
сфера с шипами (simplex noise), частицы, орбитальная камера.

**Запуск:** `Launch Visualizer` — открывает Godot на настроенном
мониторе в fullscreen. Превью сцены показывается в правом нижнем
углу инспектора (~5 fps).

**Что видно:**
- **Сфера** дышит и «взрывается» шипами на удары (`pulse`), гладкая
  на тональном материале, острая на шумном (`harmonicity`).
- **Палитра** — синяя в покое, бирюзовая на высоких нотах, оранжевая
  + белая вспышка на смене секций (`shiver` + `cortex_flash`).
- **Частицы** — ambient-рой плотнее на мелодии/вокале (`band_energy.mid`),
  burst-разлёт на атаках (`spectral_flux`).
- **Камера** — медленный облёт сферы (idle), не зависит от playback —
  сцена «живая» на паузе.

**Настройка:** Settings → «3D visualizer tuning» — скорость камеры,
Y-амплитуда, количество частиц. Палитра и поведение от событий —
через JSON-правила (Reload Rules, без перезапуска Godot для цветов;
для шейдерных констант — перезапуск).

**2D fallback:** `main_scene` в `project.godot` указывает на `spike.tscn`.
Чтобы вернуться к 2D-квадрату (эпоха MVP-B), временно переключи
`main_scene` на `node_2d.tscn` в редакторе Godot.

**Phase 2 закрыт.** Сцена полностью реагирует на события и continuous
из `.nvproj` (schema v3), preview в инспекторе, настройки в UI.
Дальнейшее развитие — Phase 2.5 (motif, export, cross-platform,
node-graph). Текущее состояние — стабильный инструмент для соло-
использования и показа.

### 🧠 Neural visualizer (Phase 2.5 — вторая 3D-сцена)

Вторая 3D-сцена, независимая от spike. Двухполушарная нейросинаптическая
сеть: узлы-нейроны, рёбра-аксоны, corpus callosum (жгут связей между
полушариями). Реагирует на те же события, что и spike, но визуально
радикально другая — «сеть живёт своей жизнью».

**Что происходит на экране:**
- **Узлы** дышат — `band_energy.low/mid/high` подсвечивают Low/Mid/High
  слои. Cascades от `pulse` (onset) — волна вспышек расходится по сети
  за ~600 ms.
- **Эволюционная перестройка:** на `stream_boundary` (смена секции)
  ~30% узлов переезжает в новые позиции внутри своих слоёв, старые
  связи рвутся, формируются новые. Это не «смена конфигурации» —
  топология действительно меняется.
- **CC-магистрали:** три пучка связей между полушариями (High/Mid/Low).
  Их яркость = `band_energy` соответствующего слоя. При `stream_boundary`
  поверх CC-жгутов происходит «осцилляция» в такт волне сжатия.
- **Частицы:** фиолетовые «нейротрансмиттеры» летят от узла к узлу
  на каждом hop'е каскада. Вокруг структуры — тёплое halo, density
  реагирует на `band_energy.mid`.
- **Камера** медленно облетает сцену (idle orbit), «отъезжает» (FOV +)
  на novelty.

**Включение:** Settings → «Visualizer scene» → **Neural**. Значение
применяется на Launch; при запущенном Godot — смена сцены через ComboBox
без перезапуска.

**Отличие от spike:**
- Spike = одна сфера с шипами; neural = сеть из ~1600 узлов.
- Spike статичен по топологии; neural эволюционирует на сменах секций.
- Spike лёгкий (один mesh); neural тяжёлый (1600 узлов, ~3800 рёбер,
  3 CC bundle mesh).
- Spike использует `SceneRoot` scale для pulse; neural — per-node
  transforms для каскада и wave.

**Тюнинг:** `TUNING.md` § «Уровень 4. Neural visualizer». Параметры
топологии (узлов/гемисферу, edges/node, CC density) — только при Launch
(topology immutable after generation). Параметры камеры — live.
