# NeuroViz — Руководство по настройке (Tuning)

Настройка визуализации делится на три уровня: **Детекторы (C#)**, **Правила (JSON)** и **Визуал (Godot)**.

---

## Уровень 1. Детекторы (C#)
Находятся в `src/NeuroViz.Analysis/Detectors/`. Отвечают за то, *какие события* рождаются из звука.

### OnsetDetector (Атаки, удары)
* **`historySize`** (по умолчанию `20`): Размер окна истории фреймов.
  Меньше — чувствительнее к быстрым изменениям, больше — стабильнее.
* **`thresholdMult`** (по умолчанию `2.2`): Множитель стандартного
  отклонения для порога детекции.
* **`refractorySeconds`** (по умолчанию `0.07`): Время «глухоты» после удара.
* **`confidenceCapacity`** (по умолчанию = `historySize`): Размер скользящего
  окна *событий* для percentile-confidence. Хранит силу (flux) последних N
  ударов; `confidence` = позиция текущего в этом окне (0 — слабейший из N,
  1 — сильнейший).
* **`confidenceMinHistory`** (по умолчанию = `max(3, historySize/4)`):
  Сколько событий нужно накопить, прежде чем percentile начнёт работать.
  До этого `confidence = 0.5` (нейтрально).

**Про confidence (B1a, KI-1):** до B1a формула была
`(flux − threshold) / threshold`. На тихом материале `threshold` близок
к нулю → любой удар давал `confidence = 1.0` → фильтр
`confidence: { min: 0.6 }` не работал. С B1a `confidence` = перцентиль
текущего события среди последних N событий: сильные удары — высокий
`confidence`, слабые — низкий.

**Warm-up:** первые `confidenceMinHistory` ударов (по умолчанию 3–5) имеют
`confidence = 0.5`, потому что сравнивать ещё не с чем. На треках с очень
редкими ударами (< 5 за весь трек) percentile так и не включится — это
ограничение модели, а не баг. Если начальные события критичны — понизьте
`confidenceMinHistory` или порог `confidence.min` в правиле.

### NoveltyDetector (Смена секций, «сюрприз»)
* **`alpha`** (по умолчанию `0.01`): Скорость привыкания.
* **`thresholdMult`** (по умолчанию `2.5`): Насколько «сюрприз» должен
  превышать фоновый шум.
* **`refractorySeconds`** (по умолчанию `1.5`): Не чаще 1 раза в 1.5 сек.
* **`minVolume`** (по умолчанию `0.5`): Порог тишины. Если RMS-магнитуда
  ниже — событие не рождается.
* **`confidenceCapacity`** (по умолчанию `20`): Окно *событий* для
  percentile. Novelty редкая — 20 событий ≈ 30+ секунд истории.
* **`confidenceMinHistory`** (по умолчанию `3`): Warm-up. Первые
  `minHistory` novelty-событий получают `confidence = 0.5`.

**Про confidence:** `confidence` теперь отвечает «насколько это изменение
необычно относительно последних novelty-событий на этом треке», а не
абсолютная сила сигнала. Для абсолютных правил используйте
`params.error_magnitude` (это то, что делает `novelty-shiver` в
`basic.json` — фильтр `error_magnitude: { min: 4.0 }`).

### PitchDetector (Высота тона через HPS)
* **`refractorySeconds`** (по умолчанию `0.05`): Не чаще 20 раз в секунду.
* **`confidenceCapacity`** (по умолчанию `20`): Окно событий ≈ 1 секунда.
* **`confidenceMinHistory`** (по умолчанию `5`): Warm-up.

**Про confidence:** `maxHps / (maxHps + 10)` больше не используется.
Причина (KI-1): на пианино `maxHps` в сотни → `confidence ≈ 0.97–1.0`
для каждой ноты. Теперь `confidence` — перцентиль `maxHps` среди
последних pitch-событий: на однородном материале (все ноты чистые)
`confidence ≈ 0.5` — честно, потому что ни одно событие не выделяется.
На смешанном (чистые/шумные, тихие/громкие) чистые и громкие ранжируются
выше. Абсолютный `maxHps` сохранён в `params.hps_strength`.

**Практическое следствие:** правило `pitch-brightness` в `basic.json`
использует `param_from_event: "pitch_norm"` — не зависит от
`confidence`, работает как раньше. Пользовательские правила с фильтром
`confidence: { min: X }` на pitch теперь дают «только выделяющиеся
события», а не «все события с чистым тоном».

### AzimuthDetector (Стереопанорама через ILD)
* **`refractorySeconds`** (по умолчанию `0.05`): Не чаще 20 раз в секунду.
* **`confidenceCapacity`** (по умолчанию `20`): Окно событий ≈ 1 секунда.
* **`confidenceMinHistory`** (по умолчанию `5`): Warm-up.

**Про confidence (изменение семантики!):** раньше `confidence = |ildNorm|`
— абсолютная величина панорамы (0 = центр, 1 = полный пан). Теперь —
перцентиль `|ildNorm|` среди недавних событий: «насколько это
паннуто необычно для этого трека». На стабильно-центрированном материале
все события ≈ 0.5 (не выделяются); на треке с редкими пан-ударами
они ранжируются высоко.

**Правило `azimuth-pan` не затронуто:** оно использует
`param_from_event: "azimuth_norm"` — абсолютный ILD (-1..+1), не
`confidence`. Пользовательские правила, которые фильтровали по
`confidence` у azimuth, увидят другой диапазон значений — правьте
пороги или переходите на `params.azimuth_norm`.

### OffsetDetector (Затухания, «выдохи»)
Зеркало `OnsetDetector` на падающем фронте спектра. Срабатывает в момент
резкого затихания — конец ноты, конец фразы, начало паузы.

* **`historySize`** (по умолчанию `20`): Окно истории фреймов для порога
  на `decline` (= magnitude отрицательного flux).
* **`thresholdMult`** (по умолчанию `2.2`): Множитель std — как у onset.
* **`refractorySeconds`** (по умолчанию `0.07`): Время после offset,
  когда новый не срабатывает.
* **`confidenceCapacity`** (по умолчанию = `historySize`): Окно *событий*
  для percentile. Аналог onset.
* **`confidenceMinHistory`** (по умолчанию = `max(3, historySize/4)`):
  Warm-up. Первые `minHistory` offset'ов получают `confidence = 0.5`.

**Params:** `decline` (текущая величина падения), `threshold` (порог).
Для фильтров на абсолютную силу падения используйте
`params.decline: { min: N }`; для относительной — `confidence: { min: X }`
(как в `offset-release`: `min: 0.6`).

**Про warm-up:** первые 3–5 offset'ов имеют `confidence = 0.5` — сравнить
не с чем. Если в треке меньше 5 затиханий (сплошной эмбиент) — confidence
так и останется 0.5 для всех; правило `offset-release` с `min: 0.6` их
отсечёт. Это корректное поведение: «не с чем сравнить» → не выделяем.

## Уровень 1.5. Continuous params (B2)

Помимо дискретных событий, пайплайн эмитит **непрерывные метрики** —
по одному `float` на ключ за STFT-кадр (~40 Гц). Они попадают в
`EventStreamFrame.ContinuousParams` и используются визуализатором
**напрямую** (без `EvaluateAt`, без decay, без истории).

**Отличие от events:** events имеют `Confidence` и затухают через
`ParamValue.EvaluateAt`; continuous — просто последнее известное
значение метрики. Если метрика перестала приходить (silence или
replay), визуализатор держит последнее значение.

### Доступные continuous-ключи

| Ключ | Диапазон | Источник | Смысл |
|---|---|---|---|
| `spectral_centroid` | 0..1 | `SpectralFeaturesDetector` | Яркость спектра (высокие частоты → 1) |
| `harmonicity` | 0..1 | `SpectralFeaturesDetector` | 1 = чистый тон, 0 = шум |
| `band_energy.low` | 0..1 | `BandEnergyDetector` | Доля энергии 20–250 Гц (бас, бочка) |
| `band_energy.mid` | 0..1 | `BandEnergyDetector` | Доля энергии 250–2000 Гц (мелодия, вокал) |
| `band_energy.high` | 0..1 | `BandEnergyDetector` | Доля энергии 2000–8000 Гц (hi-hats, воздух) |

**Свойства `band_energy` (B3):**
- Три полосы **не перекрываются** → `low + mid + high = 1.0` при ненулевой энергии.
- **Нормированы на общую энергию** — не зависят от громкости: тихий бас и громкий бас дают одинаковый `band_energy.low`.
- В тишине (`total < 1e-5`) все три = 0.0 (активный ноль, чтобы визуализатор «схлопнулся», а не замер на последних громких значениях).

### Band energy в MainNode (B5)

Три полосы — три независимых визуальных канала на главном квадрате:

| Band | Канал | Формула (в `MainNode._Process`) | Эффект |
|---|---|---|---|
| `band_energy.low` | **scale** | `targetScale = max(0.3, 1.0 + pulse*0.5 - release*0.35 + smoothLow*0.4)` | Квадрат «дышит» в такт бочке даже без onset'ов |
| `band_energy.mid` | **hue** | `color.Lerp(teal, smoothMid * 0.4)` | Мелодичные/вокальные секции → от синего к бирюзовому |
| `band_energy.high` | **brightness** | `color.Lerp(white, smoothHigh * 0.5)` | Яркие секции (тарелки, синты) → белый |

**Сглаживание:** `kb = 1 - exp(-12*delta)` (τ ≈ 83 мс). Чуть медленнее
event-параметров (`k`, τ ≈ 40 мс) — band_energy шумит на 40 Гц, и без
сглаживания квадрат «дрожал» бы вместо «дыхания». При этом 83 мс хватает,
чтобы отслеживать kick с периодом 200–500 мс без видимого лага.

**Значения — доли от общей энергии спектра, не абсолютные RMS.** Это
значит, что на тихом пианино `band_energy.low` может быть 0.6 (если трек
басовый), а на громком хэви-метале — 0.3 (если там доминируют гитары в
mid). Это корректное поведение: визуализация отражает **характер**
спектра, а не громкость.

**Тюнинг силы эффекта:** коэффициенты `0.4`, `0.4`, `0.5` в формулах
выше — в `MainNode._Process`. Увеличьте для более драматичного
«дыхания» / цветовых сдвигов; уменьшите для сдержанности.

### VAD: `vad_state` + `speech_music_ratio` (C1)

`VadDetector` — непрерывная детекция речи. Эмитит два ключа:

| Ключ | Диапазон | Смысл |
|---|---|---|
| `vad_state` | 0 or 1 | Речь в этом фрейме (гистерезис) |
| `speech_music_ratio` | 0..1 | Характер секции: >0.5 = речь, <0.5 = музыка (EMA, τ ≈ 2 s) |

**Модель:** soft-min четырёх признаков. `score = 0.7·min + 0.3·avg`,
где каждый признак ∈ [0, 1] с soft-window. Soft-min (а не сумма)
потому что VAD — это AND: чистый бас имеет centroid и ZCR
не-речевого диапазона, но flatness ≈ 0 (pure tone) — сумма дала бы
ложный «on». Min обнуляет score при единственном провале, avg
смягчает переходы.

**Признаки (хардкодятся в `VadDetector`):**

| Признак | Речевой диапазон | Вне диапазона |
|---|---|---|
| Voice-band fraction (300–3000 Hz) | > 0.65 | < 0.30 → 0 |
| Centroid | 300–2500 Hz | < 150 Hz или > 7.5 kHz → 0 |
| Flatness | 0.05–0.55 | 0 (pure tone) или 1 (noise) → 0 |
| ZCR | 0.02–0.20 | 0.005 (bass tone) или 0.5 (white noise) → 0 |

**Hysteresis:** enter at 0.55, exit at 0.40. Между порогами — состояние
не меняется. Это защищает от «дребезга» на граничных фреймах.

**`speech_music_ratio` — EMA `vad_state` с τ ≈ 2 s** (α ≈ 0.012 при
40 Hz). Отвечает «эта секция — речь или музыка», а не «этот фрейм».
200 фреймов речи подряд → ratio → 1.0 (≈ 5 s). 200 фреймов тишины →
ratio → 0.0.

**Тюнинг порогов:**
- Если на инструментале с вокалом в припеве VAD «мигает» — увеличьте
  `vadOffThreshold` (сложнее выключить) или `vadOnThreshold` снизьте.
- Если на чистом инструментале VAD ложно срабатывает (гитара/скрипка
  попадают в речевые диапазоны) — поднимите `vadOnThreshold` к 0.65–0.7
  или сузьте `FlatnessHi` до 0.45.
- Конструктор принимает `ratioTimeConstantSeconds` (default 2.0),
  `vadOnThreshold` (0.55), `vadOffThreshold` (0.40).

**ZCR из `SpectralFrame.ZeroCrossingRate`:** считается в
`StftBuffer.ProcessFrame` по сырому ring-buffer (до Hann-окна). Это
не phase info, а именно crossings — обнуляется на DC и нарастает
к высоким частотам / шуму.

### Stream Boundary: `stream_boundary` (C2)

Sticky-состояние «открыта ли глава». Эмитит событие `stream_boundary`
с `params.open = 1` (глава началась) или `= 0` (глава закончилась).
Правила `stream-open` / `stream-close` в `basic.json` реагируют на
`params.open` через `eq: "1"` / `eq: "0"`.

**Двойная роль:** `StreamBoundaryDetector` реализует и
`IEventDetector` (проверка таймаута на каждом фрейме), и
`IEventObserver` (приём novelty-событий). Регистрируется дважды на
одном pipeline — как детектор и как observer.

**Правила:**

| Что | Значение по умолчанию | Смысл |
|---|---|---|
| Strong novelty | `confidence ≥ 0.75` **или** `error_magnitude ≥ 4.0` | Сигнал «смена секции» |
| Open window | 4 с | Два strong-novelty в этом окне → open |
| Open count | 2 | Один novelty = drum fill, не секция |
| Close timeout | 8 с | 8 с без strong-novelty → close |
| Refractory | 2 с | Между open-событиями — пауза |

**Почему 2 novelty:** один громкий барабанный филл — не смена
секции. Два strong-novelty в течение 4 с — уже структурное событие
(куплет → припев, смена динамики, смена инструментовки).

**Почему refresh, а не re-emit:** пока стрим открыт, strong-novelty
обновляет `lastStrongNovelty` — таймаут close отодвигается. Новый
open не эмитится (правило `stream-open` не должно срабатывать на
каждой смене аккорда внутри секции). Это sticky state: одно событие
на границу, а не на каждое изменение.

**Тюнинг:**
- Если на спокойных треках стрим «закрывается» слишком быстро —
  увеличьте `closeAfterSeconds` (12–15 с).
- Если на шумных треках открывается слишком часто — поднимите
  `strongConfidence` к 0.85 или `openRequiredCount` к 3.
- Для полностью предсказуемого поведения на размеченных треках —
  `refractorySeconds: 5` (границы реже, чем раз в 5 с).

**Отличие от continuous:** `stream_boundary` — **событие**, не
continuous. Оно сохраняется в `.nvproj` (это `AudioEvent`), доступно
в Debug-таблице, и его можно фильтровать правилами. Sticky-состояние
самого детектора (`_isOpen`) — runtime-only, не переживает load;
см. `docs/KNOWN_ISSUES.md` (KI-2-родственный нюанс, отдельно не
фиксируется т.к. событие-граница в timeline есть).

## Уровень 2. Правила (JSON)
Файл `samples/rules/basic.json`. Связывают события со «свойствами» (параметрами) визуализатора.

### Структура правила
* **`id`**: Уникальное имя.
* **`event`**: Тип события (`onset`, `novelty`).
* **`filters`**: Условия срабатывания.
  * `confidence: { min: 0.6 }` — минимальная уверенность детектора.
  * `params.error_magnitude: { min: 4.0 }` — сила «сюрприза» для novelty.
* **`actions`**: Что сделать с визуалом.
  * **`param`**: Имя параметра (например, `pulse`, `shiver`).
  * **`value`**: Начальное значение (обычно `1.0`).
  * **`decayMs`**: Время затухания параметра до нуля в миллисекундах. `150` — быстрый удар, `1000` — медленная волна.

## Уровень 3. Визуал (Godot)
Файл `src/NeuroViz.Visualizer/Scripts/MainNode.cs`.
Отвечает за то, как параметры превращаются в картинку.

### Маппинг параметров
* **`pulse`** (от onset): Управляет **масштабом** (`Scale`). В коде: `scale = 1.0f + currentPulse * 0.5f`. Если хотите, чтобы квадрат раздувался сильнее, меняйте `0.5f` на `1.0f`.
* **`shiver`** (от novelty): Управляет **цветом** (`Color`). В коде: `Lerp(baseColor, targetColor, currentShiver)`.
  * `baseColor` — базовый синий `(0.2, 0.6, 1.0)`.
  * `targetColor` — оранжевый `(1.0, 0.5, 0.0)`.
  * Если хотите красный цвет — меняйте `targetColor` на `(1.0, 0.0, 0.0)`.
* **`release`** (от offset): Уменьшает **масштаб** (`Scale`). В коде:
  `scale = max(0.3, 1.0 + pulse*0.5 - release*0.35)`. Пульс раздувает,
  release сжимает — «вдох/выдох» в такт. Если хотите более резкий
  выдох — увеличьте `0.35f`; для «намёка» — уменьшите до `0.2f`.

### Затухание
Параметры в Godot вычисляются через `ParamValue.EvaluateAt(clock)`, который экспоненциально затухает на основе `decayMs` из JSON. Визуал всегда плавный, независимо от частоты кадров.
