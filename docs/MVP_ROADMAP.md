# NeuroViz — Roadmap до полного MVP

Документ фиксирует, что осталось до состояния «полный MVP», и в каком
порядке. Полный MVP определён как замкнутый цикл без ручного
редактирования C#/JSON:

> Открыл трек → проанализировал → настроил правила → увидел →
> сохранил → через неделю открыл проект → увидел без повторного
> анализа.

Оценки — рабочие дни одного человека в темпе «соло-разработка по
вечерам». Каждая итерация заканчивается рабочим состоянием, которое
можно показать.

---

## Обзор тиров

| Тир | Цель | Оценка |
|---|---|---|
| MVP-A | Замкнуть цикл save → load → save | ~3 дня |
| MVP-B | Сенсорика: continuous params + band_energy + offset | ~4–5 дней |
| MVP-C | Семантика: vad, speech_music_ratio, stream_boundary | ~4–6 дней |
| MVP-D | UX polish: shortcuts, waveform, settings, re-analyze | ~2 дня |
| **Итого** | | **~2 недели** |

**Правило порядка:** нельзя брать шаг из следующего тира, пока не
закрыты все его зависимости из предыдущих (см. «Зависимости» в каждом
тире). Причина — избежать переделки.

## MVP-A — замкнуть цикл (~3 дня)

Без этого проекта нет: save есть, load нет.

### A1. Load project (.nvproj)
- `ProjectLoader` — отдельный класс в `NeuroViz.Project` (или App, если
  нужен доступ к `AppSettings`).
- `MainWindowViewModel.LoadProjectAsync(projectPath, overrideAudioPath?)`.
- Кнопка **Load project…** рядом с **Open…**.
- Восстановление `Events`, `_eventKeys`, правил, аудио, состояния.
- Диалог поиска аудио, если путь в проекте не резолвится.
- **Подробный план:** `docs/PLAN_A1_LOAD_PROJECT.md`.

**Готово когда:** сохранили проект, закрыли App, открыли заново,
нажали Load project → видны все события, Play работает, Seek работает,
история воспроизводится без повторного анализа.

### A2. Resilience аудио-пути
- При **сохранении** писать в `Timeline.AudioPath` **относительный**
  путь от `.nvproj` (fallback на абсолютный, если на разных дисках).
- При **загрузке** резолвить в порядке: абсолютный → имя рядом с
  `.nvproj` → относительный от `.nvproj` → диалог.
- Сохранять `AudioSha256` и сверять при загрузке; при несовпадении —
  предупреждение «Audio changed, timeline may be misaligned».

**Готово когда:** проект + аудио перенесли в другую папку —
открывается без диалога.

### A3. Ошибки загрузки
- Явные исключения: `ProjectNotFoundException`,
  `ProjectCorruptException`, `ProjectVersionTooNewException`,
  `AudioNotFoundException`, `AudioIntegrityMismatch` (не исключение,
  флаг в результате).
- 4–5 конкретных сообщений в `StatusText` вместо голого
  `JsonException` / `MessagePackSerializationException`.

**Готово когда:** каждое из пяти состояний (файла нет / битый / версия
новее / аудио нет / хеш не совпал) даёт понятное сообщение и не
роняет приложение.

### A4. Reload rules без рестарта
- Кнопка **Reload Rules** (или авто-детект `mtime` файла правил).
- `RuleEngine` пересоздаётся из `_rulesDocument`, `_rulesDocument`
  перечитывается из `Settings.RulesPath` → bundled → dev-fallback.
- Не менять `_projectSource` и не сбрасывать события.

**Готово когда:** отредактировали `samples/rules/basic.json` в
редакторе → нажали Reload Rules → новые пороги применились к
следующему же событию, без перезапуска.

### Зависимости MVP-A
- A1 → A2, A3 (естественно продолжают друг друга)
- A1 → A4 (нет смысла перезагружать правила, если и так всё в памяти,
  но логично сделать сразу после load, чтобы «текущее состояние»
  было единым для save/load)

## MVP-B — сенсорика (~4–5 дней)

Здесь появляются новые события **и** инфраструктура непрерывных
параметров.

### B1. KI-1: Confidence model
- Определить контракт `AudioEvent.Confidence`: **absolute** vs
  **percentile** vs **hybrid**.
- Переработать 5 детекторов (`Onset`, `Novelty`, `Pitch`, `Azimuth`,
  `SpectralFeatures`).
- Обновить `TUNING.md`.
- Тесты: тихий / громкий / разреженный / плотный материал.

**Готово когда:** на C418 Sweden `confidence` **не** насыщается в 1.0
на каждом событии; фильтры правил работают на разреженном материале.

**Почему раньше B3/B4:** иначе новые детекторы унаследуют ту же
проблему, и `band_energy` будет насыщаться на тихом пианино.

### B2. Continuous params infrastructure
- Тип `ContinuousParam` (или `float`-пара в отдельном словаре).
- Поле `ContinuousParams` в `EventStreamFrame`.
- В Godot: `MainNode._Process` использует непрерывные значения
  **напрямую** (без `EvaluateAt`, без `decayMs`).
- Синхронизация с MMF-часами как в фиксе 4.9 (уже работает).

**Готово когда:** в Godot можно нарисовать квадрат, чей scale
**непрерывно** следует за `band_energy.low` без событий.

**Почему до B3/B4:** `band_energy` и `spectral_flux` естественно
непрерывны; эмитить их как «события» — костыль.

### B3. `band_energy` (continuous, 3 полосы)
- Низ: 20–250 Гц. Середина: 250–2000 Гц. Верх: 2000–8000 Гц.
- RMS по бинам FFT внутри полосы, нормированный на общий RMS (чтобы
  шкала не зависела от громкости).
- Эмитится каждый кадр STFT (~40 Гц) в continuous-канал.

**Готово когда:** правило `band_energy.low → base_scale` даёт
«дыхание» квадрата в такт бочке.

### B4. `offset` (событие)
- Зеркало onset на падающем фронте spectral flux.
- Логика: `flux < -threshold` вместо `flux > threshold`.
- `Confidence` — по модели из B1.

**Готово когда:** на треке с паузами `offset` срабатывает в конце
фраз; правило `offset → release_decay` даёт визуальный «выдох».

### B5. Rules + Visualizer
- `basic.json`: три правила для `band_energy.{low,mid,high}` и одно
  для `offset`.
- `MainNode`: три независимых визуальных канала (scale, hue, glow),
  «выдох» от offset.

**Готово когда:** на реальном треке визуал перестаёт быть
«монотонным пульсом» и получает три тела-канала + дыхание.

### Зависимости MVP-B
- B1 → B4 (offset confidence = по модели)
- B2 → B3 (band_energy в continuous)
- B3 → B5 (правила ссылаются на band_energy)
- B4 → B5 (правила ссылаются на offset)

## MVP-C — семантика (~4–6 дней)

| Шаг | Что | Оценка | Зависит от |
|---|---|---|---|
| C1 | `vad_state` + `speech_music_ratio` — простая VAD (ZCR + spectral flatness + полоса 300–3000 Гц), эмитится в continuous | 1–2 дня | B2 |
| C2 | `stream_boundary` — порог на novelty со sticky-состоянием (открытие/закрытие «главы»), правило `stream-open` наконец заработает | 1 день | B1 |
| C3 | `spectral_flux` наружу — сейчас считается внутри Onset, вынести как continuous-метрику | полдня | B2 |
| C4 | Rules + Visualizer — VAD → переключение визуального слоя, boundary → смена палитры | 1 день | C1, C2 |

**Готово когда:** на треке с вокалом визуал переключается между
«инструментал» и «голос» слоями; на смене секции — визуальный
«разрыв главы»; сырой flux управляет общей яркостью.

| Шаг | Что |
|---|---|
| D1 | Keyboard shortcuts: Space = play/pause, ←/→ = seek ±5 с, Home = в начало |
| D2 | Waveform на таймлайне — пики по 100–200 бакетам |

**Готово когда:** продукт можно показать человеку с улицы, и он не
спросит «а где тут кнопка плей».

## Что НЕ входит в MVP

Сознательно отложено, чтобы не раздувать срок:

- Своя реализация FFT/STFT — используем FftSharp, NWaves.
- Rule-engine на графах — JSON справляется.
- Embedding Godot в инспектор — см. обсуждение в чате; preview-
  thumbnail в фазе 2 даст 80% пользы за 5% усилий.
- Синхронизация с DAW (VST/AU).
- Облачные сохранения / sharing / коллаборация.
- Multi-track (несколько аудио на одном таймлайне).

## Критерий «полный MVP»

Одна связная история:

1. Пользователь запускает App, выбирает аудио, настраивает правила
   через JSON + Reload.
2. Видит визуализацию на **своём** материале (тихом, громком,
   разреженном, плотном) без схода с ума.
3. Space/←/→ работают как в любом плеере.
4. На таймлайне видна структура трека.
5. Сохраняет проект, закрывает App, через неделю открывает `.nvproj` —
   продолжает с того же места.
